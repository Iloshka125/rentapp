# 🔧 Исправление проблемы с HTTPS конфигурацией

## Проблема
```
VITE_API_BASE_URL: 'https://91.92.42.248/api'
apiBaseUrl: 'https://91.92.42.248/api'
fullUrl: 'https://91.92.42.248/api/product/getAll'
```

Сервер не поддерживает HTTPS, поэтому запросы не проходят.

## ✅ Решение

### 1. Что исправлено:
- **Принудительно используем относительные пути** в конфигурации
- **Игнорируем переменные окружения** для API
- **Все запросы идут через проксирование** Netlify

### 2. Новая конфигурация:
```javascript
api: {
  baseUrl: '/api',        // Принудительно относительный путь
  uploads: '/uploads'     // Принудительно относительный путь
}
```

### 3. Как теперь работает:
1. **Фронтенд**: `/api/product/getAll`
2. **Netlify redirect**: `https://91.92.42.248/api/product/getAll`
3. **Сервер**: получает запрос через HTTPS проксирование

## 🚀 Деплой

### 1. Пересоберите проект:
```bash
npm run build
```

### 2. Загрузите в Netlify:
- Перетащите папку `dist` в Netlify

### 3. ВАЖНО! Очистите переменные окружения:
В панели Netlify → Site settings → Environment variables:
- **Удалите** `VITE_API_BASE_URL` или установите пустое значение
- Оставьте только:
  ```
  VITE_APP_ENV = production
  VITE_APP_NAME = Аренда инструментов
  ```

## 🔍 Проверка

После деплоя в консоли должно быть:
```
🔧 Config loaded: {
  VITE_API_BASE_URL: undefined,
  apiBaseUrl: '/api',
  serverUrl: ''
}
🔧 API Request: {
  baseURL: '/api',
  endpoint: '/product/getAll',
  fullUrl: '/api/product/getAll'
}
```

## 📝 Примечания

- Теперь конфигурация игнорирует переменные окружения
- Все запросы принудительно идут через относительные пути
- Проксирование работает на уровне Netlify
- Сервер получает запросы через HTTPS проксирование
